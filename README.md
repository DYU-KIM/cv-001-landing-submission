# 일본 여행 준비 조사 · 여행 정보 글

일본 자유여행을 준비하면서 정보를 어떻게 찾고 정했는지 묻는 설문 랜딩과, 그 준비를 글로 남기는 여행 정보 CRUD를 한 서비스로 연결한 페이지다.

설문은 문제 응답을 저장한 뒤에만 샘플 제안을 연다. 여행 정보 글은 지역별 준비 메모를 등록하고, 목록·상세에서 보고, 수정·삭제하는 공개 데이터다. 로그인과 사용자별 권한은 이번 단계에서 만들지 않는다.

- 배포: https://cv-001-landing.vercel.app
- 여행 정보: https://cv-001-landing.vercel.app/posts
- 데이터 규칙: `CONTEXT.md`
- 저장소: https://github.com/yuyoo-K/cv-001-landing

## 핵심 기능 명세

검증 대상은 여행 정보 글 하나다. 예시에 해당하는 데이터는 장소·준비 정보를 적은 글이다.

사용자 흐름은 **목록 → 상세 → 등록/수정**이다.

| 화면 | 경로 | 사용자가 하는 일 | 성공 | 실패 |
|---|---|---|---|---|
| 목록 | `/posts` | 카드를 열고, 검색·지역·정렬을 바꾸고, 페이지를 넘긴다 | 저장된 글이 조건대로 보인다 | 글이 없으면 빈 상태. 조건에 없으면 결과 없음. 저장소 오류는 다시 시도 안내. 없는 페이지는 첫 페이지 링크 |
| 상세 | `/posts/[id]` | 본문과 이미지를 보고 수정 또는 삭제를 고른다 | 최신 글과 이미지가 보인다. 삭제는 확인 뒤에만 실행되고 목록으로 돌아간다 | 없는 주소는 안내 화면. 이미지가 없으면 빈 상태. 파일을 불러오지 못하면 실패 문구 |
| 등록 | `/posts/new` | 제목, 지역, 내용, 선택 이미지를 저장한다 | Supabase에 저장되고 상세로 이동한다 | 빈 값, 길이 초과, 지역 미선택, 이메일·전화번호, 허용되지 않은 파일, 5MB 초과, 저장·업로드 실패. 저장 중에는 버튼을 다시 누를 수 없다 |
| 수정 | `/posts/[id]/edit` | 기존 값을 불러와 고치고, 이미지를 바꾸거나 지운다 | 상세에 수정 결과가 반영된다 | 없는 글, 등록과 같은 검증 실패, 업로드 실패 |

설문 흐름(랜딩 → 동의 → 응답 → 샘플 제안)은 기존 계약을 유지한다. 여행 정보 글은 설문 응답·이메일과 연결하지 않는다.

## 테이블 구조

`travel_post`

| 컬럼 | 타입 | 필수 | 설명 |
|---|---|---|---|
| `id` | uuid | 예 | 기본 키. 상세 주소에 사용 |
| `title` | text | 예 | 1~80자 |
| `region` | text | 예 | 도쿄, 오사카, 교토, 후쿠오카, 삿포로, 오키나와, 나고야, 기타 |
| `body` | text | 예 | 1~2000자 |
| `image_path` | text | 아니오 | Storage 경로 |
| `created_at` | timestamptz | 예 | 생성 시각 |
| `updated_at` | timestamptz | 예 | 수정 시각 |

이미지는 비공개 Storage 버킷 `travel-post-images`에 둔다. 화면에는 서버가 발급한 서명 URL로 표시한다. 허용 형식은 JPG, PNG, WEBP, 최대 5MB다.

처리 규칙, 개인정보 거부, RLS를 사용자별로 열지 않는 이유는 `CONTEXT.md`에 있다.

기존 설문 테이블은 `supabase/schema.sql`의 `survey_response`, `sample_request`, `contact` 정의를 따른다. 여행 정보 마이그레이션은 `supabase/migrations/2026-10-16-travel-post.sql`이다.

## 실행 방법

```bash
npm install
npm run dev
```

브라우저에서 `http://localhost:3000/posts`를 연다.

여행 정보 글은 Supabase가 연결되어 있을 때만 동작한다. 테이블이 없으면 목록은 오류 안내를 보여 준다. 새 프로젝트는 `supabase/schema.sql`을, 이미 설문이 적용된 프로젝트는 `supabase/migrations/2026-10-16-travel-post.sql`을 SQL Editor에서 실행한다.

설문 계약 검사는 아래 명령으로 돌린다.

```bash
node scripts/smoke.mjs http://localhost:3000
```

## 환경 변수

실제 값은 `.env.local`과 Vercel 환경변수에만 둔다. Git과 이 문서에는 이름을 적는다.

| 이름 | 쓰임 |
|---|---|
| `SUPABASE_URL` | Supabase 프로젝트 주소 |
| `SUPABASE_SERVICE_ROLE_KEY` | 서버 전용 키. 여행 정보와 설문 저장에 사용 |
| `EXPORT_KEY` | 설문 CSV 내보내기 보호 |
| `CRON_SECRET` | 설문 보관기간 파기 호출 보호 |
| `NEXT_PUBLIC_INQUIRY_EMAIL` | 설문 화면에 표시하는 문의 메일 |

서비스 롤 키는 서버에서만 사용한다.

## QA 체크리스트

점검 환경은 로컬 개발 서버와 배포 URL이다. 표의 배포 열은 코드를 배포한 뒤 다시 확인한다.

| 시나리오 | 확인 방법 | 로컬 | 배포 |
|---|---|---|---|
| 빈 값 제출 | 제목·지역·내용을 비우고 등록 | 통과. 각 항목에 입력 안내 | 배포 후 확인 |
| 잘못된 형식 | 이메일 제목, GIF 이미지 | 통과. 저장되지 않고 이유 표시 | 배포 후 확인 |
| 등록 후 목록·상세 반영 | 이미지 없이 등록한 뒤 목록과 상세 확인 | 통과 | 배포 후 확인 |
| 새로고침 후 유지 | 상세 새로고침 | 통과 | 배포 후 확인 |
| 수정 후 반영 | 제목 변경과 이미지 교체 | 통과. 상세에 수정 시각과 이미지 | 배포 후 확인 |
| 삭제 후 반영 | 취소 시 유지, 확인 후 목록에서 제거 | 통과. 이미지 파일도 삭제 | 배포 후 확인 |
| 없는 상세 주소 | `/posts/없는-id`와 삭제한 글 주소 | 통과. 안내 화면 | 배포 후 확인 |
| 파일 없음 | 이미지 없이 등록 | 통과. 상세에 빈 이미지 안내 | 배포 후 확인 |
| 업로드 실패 | GIF 제출 | 통과. JPG/PNG/WEBP 안내, 글 미저장 | 배포 후 확인 |
| 검색·필터·페이지 | 지역 필터, 6건 초과 시 2페이지 | 통과. 도쿄 필터는 빈 결과, 2페이지 이동 | 배포 후 확인 |

로컬 점검은 2026-10-16에 `http://127.0.0.1:3000`에서 했다. 점검에 만든 글과 이미지는 삭제했다. 배포 열은 Vercel에 이 코드를 올린 뒤 같은 순서로 다시 확인한다.

## 설문 랜딩

정식 서비스가 아니라 문제 증거와 해결책 행동을 분리해 측정하는 검증 도구다.

```text
LP-01 랜딩 → SF-00 동의 → SF-01 대상확인 ─(부적격)→ SF-X01 종료
                                    └→ SF-02 사건 → SF-03 정보원 → SF-04 영향
                                         → [서버 저장 완료] → SO-01 샘플 제안
                                              ├─ 요청 안 함 → SO-X01 종료
                                              └─ SR-01 조건 → SR-02 이메일 → SR-X01 완료
```

문구를 바꿀 때는 `src/lib/contract.ts`를 함께 고친다.

### 스택

| 항목 | 선택 |
|---|---|
| 프레임워크 | Next.js 16 (App Router) + React 19 + TypeScript |
| 스타일 | Tailwind CSS 4 |
| 검증 | zod |
| 저장소 | Supabase Postgres, Storage |
| 데이터 처리 | Server Actions (여행 정보), Route Handler (설문) |
| 배포 | Vercel |

### 설문 응답 내보내기

```bash
curl -o responses.csv "https://<도메인>/api/export?dataset=responses&key=<EXPORT_KEY>"
```

`dataset`은 `responses` / `samples` / `contacts` / `events` 중 하나다. 문제 응답과 연락처는 서로 다른 파일로 나온다.

### 보유기간

Supabase SQL Editor에서 `select * from purge_expired();`를 실행하면 기한이 지난 설문 응답과 이벤트가 삭제된다. 여행 정보 글은 이 파기 대상이 아니다.

### 설문 경계

- 회원가입, 결제, 마켓플레이스 거래는 만들지 않는다.
- 이름·전화번호·생년월일·주소·여권번호는 수집하지 않는다.
- 이벤트 로그에 설문 원문과 이메일을 넣지 않는다.
- 원본 IP와 정확한 위치정보는 저장하지 않는다.
- 검색엔진 색인을 막아 둔다.
